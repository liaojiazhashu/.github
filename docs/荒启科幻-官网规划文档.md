## 一、项目目标与范围

### 1.1 建设目标

把「荒启科幻」从一段品牌介绍，转化为一个具备企业级视觉可信度的官方网站，完成三件事：

1. **说清自己**：让访客在首屏 5 秒内理解荒启科幻是什么公司、做什么、和谁有关。
2. **说透业务**：三大板块（科幻社群 / 社群工具开发 / 文学分析）各有独立页面，讲清模式、功能、产出与适用对象。
3. **促成动作**：为写作者、文学组织、研究者分别提供明确的下一步入口（加入社群、咨询定制、索取分析样例）。

### 1.2 范围

- 7 个静态页面的完整设计、编码与内容填充
- 一套可复用的视觉设计系统（Design Tokens + 组件库）
- 品牌 Logo 处理（反白版、透明底版）
- 专业中英文字体本地化（自托管，不依赖任何 CDN）
- 桌面 / 笔记本 / 平板 / 手机 / 超宽屏全断点适配
- 基础交互：导航、筛选、折叠、滚动动效、表单校验

### 1.3 不在本期范围

- 后端服务、数据库、真实登录注册、真实表单投递服务
- 内容管理系统（CMS）
- 真实作品数据接口对接（本期使用前端静态数据文件，后续可替换）

### 2.3 图形语言

全部由 CSS 与内联 SVG 绘制，位图仅用于品牌 Logo 与照片：

1. **几何破片（Ray Shards）**：从 Logo 的放射结构提炼 6–9 条锐角多边形，作为 Hero 与区块标题的装饰元素，低透明度、轻微视差。
2. **星野（Starfield）**：三层视差星点 + 缓慢漂移 + 独立相位闪烁，见 2.6 星球特效层。
3. **网格（Grid）**：1px 低透明网格线，用于 Hero 与技术类区块，暗示"数据/结构"。
4. **数据线（Data Line）**：细长渐变线 + 端点圆点，用于流程、时间轴、章节序号连接。
5. **光晕（Aura）**：大范围径向渐变，仅在首屏与 CTA 区出现，控制数量。
6. **星球（Planet）**：程序化生成的巨型天体，全站背景的视觉主体，见 2.6。

### 2.5 动效规范

统一缓动 `cubic-bezier(.22,.61,.36,1)`，时长 180ms / 320ms / 560ms 三档。

- 导航：滚动超过 80px 后由透明切换为「半透明 + 毛玻璃 + 底部细线」
- 首屏：标题分行上浮 + 副标题延迟 120ms + 按钮延迟 240ms
- 列表卡片：进入视口时错峰上浮（每项 60ms 递增）
- 数字：数据条进入视口触发计数动画
- 卡片 hover：边框升色 + 上移 2px + 内部渐变光斑跟随（桌面端）
- 全站尊重 `prefers-reduced-motion: reduce`，开启时关闭所有位移动画

### 2.6 背景星球特效层（核心视觉升级）

全站固定一层 `<canvas>` 太空场景作为背景，由自研引擎 `js/space.js` 驱动。它不是贴图，而是**实时程序化渲染**：星球地表、大气辉光、行星环、星云、流星全部在运行时生成，因此在任何分辨率下都保持锐利，并可通过参数化让每个页面拥有不同的「星球场景」。

#### 2.6.1 图层结构（由远及近）

| 层 | 内容 | 动态 |
| --- | --- | --- |
| L0 深空底 | 星云贴图自带的大尺度底色（深空蓝紫 → 更深的同色系），**全屏不透明** | 静态 |
| L1 星云 | 3–4 团大型柔和色斑（紫 / 青 / 靛），逐像素域扭曲密度场 + 两趟一维模糊 | 极缓慢漂移与膨胀，周期 90–180s |
| L2 星野 | 三层视差星点（远 / 中 / 近），尺寸与亮度递变 | 缓慢横向漂移 + 各自独立相位的呼吸闪烁 |
| L3 星球 | 程序化球体：地表纹理、明暗终止线（光来自左上）、大气边缘辉光、逆光轮辉 | 自转（纹理横向位移）、极缓慢的悬浮起伏 |
| L4 行星环（按场景启用） | 多层半透明椭圆环带，含环缝与内外径明暗过渡 | 环带纹理缓慢旋转，透视角度微变 |
| L5 卫星（按场景启用） | 1–2 颗小星体沿椭圆轨道运行，带自身明暗面 | 公转周期 120–260s |
| L6 流星 | 偶发流星，带渐隐拖尾 | 随机间隔 6–18s |
| L7 星尘 | 低密度悬浮微粒 | 缓慢上升 / 漂移 |
| L8 CSS 覆盖层 | 暗角 vignette、网格、几何破片、顶部渐变遮罩 | 滚动视差、鼠标视差 |

**层级纪律**：L0–L7 处于 `z-index: -1` 且 `pointer-events: none`，绝不影响内容可读性与交互。内容区一律叠加强化遮罩（`--bg-0` 半透明 + 局部模糊），保证正文对比度仍 ≥ 4.5:1。

> **一条容易踩的坑：星云画布是不透明的，它本身就是页面背景。**
> 星云 `ImageData` 的 alpha 通道全程写 255，绘制端用 `lighter` 合成，结果是
> 每个像素的最终 alpha 都被推满 —— 所以 `<html>` / `<body>` 上的背景色
> **在画面里完全看不到**（它只在 Canvas 不可用或 JS 被禁用时作为兜底生效）。
> 想调「页面底有多亮」，改 `--bg-*` 令牌是没用的，只能调星云的密度下限与
> `NEBULA_GAIN`。反过来，任何面板、卡片要压暗底色，也不能指望页面背景托底。

#### 2.6.2 分场景参数（`data-scene` 调用方式）

引擎以配置驱动，页面只需在 `<body>` 上声明场景名即可调用不同星球，等价于一个可复用的「动画组件」：

| 页面 | `data-scene` | 星球形态 | 色相 | 位置与构图 |
| --- | --- | --- | --- | --- |
| 首页 | `home` | 带环气态巨行星 + 1 颗卫星 | 星云紫主调 | 星球位于右侧偏下、超大尺度（直径约视口高 90%），部分出画 |
| 关于荒启 | `about` | 双星系统（主星 + 伴星） | 紫 + 靛 | 左下方，朝向左上受光 |
| 科幻社群 | `community` | 岩质星球 + 陨击环带 | 暖紫偏粉 | 右上，尺度中等 |
| 社群工具开发 | `tools` | 机械感星球 + 强化赤道环 | 数据青主调 | 右下，配合网格层 |
| 文学分析 | `analysis` | 深空星球 + 星链图谱点缀 | 深紫 + 青 | 左侧，环带近正视角 |
| 作品库 | `works` | 低存在感星球 | 中性蓝 | 右上角局部露出，避免干扰筛选阅读 |
| 联系我们 | `contact` | 静谧星空（弱星球） | 柔和紫 | 星球尺度最小，营造安静感 |

#### 2.6.3 交互响应

- **鼠标视差**：鼠标移动时，L2–L4 按 0.4 / 0.8 / 1.4 的不同系数位移，最大偏移 12px，缓动跟随（桌面端专属）
- **滚动视差**：页面下滚时星球缓慢下沉并轻微放大，星云反向位移，制造纵深
- **入场**：首屏加载后 0 → 800ms 内，星野淡入、星球自下方浮入、环带由暗转亮
- **触屏 / 移动端**：关闭鼠标视差与星尘层，降低星数

#### 2.6.4 性能与降级策略

这是本项目对性能要求最高的部分，采用以下硬性措施：

1. **离屏预渲染**：星球纹理（地表条带 + 明暗 + 辉光）只在初始化与尺寸变化时绘制到离屏 Canvas，主循环仅做 `drawImage` 合成，避免逐帧重算渐变。
2. **DPR 上限 2**：4K 屏也不超过 2 倍像素密度，防止填充率爆炸。
3. **可见性暂停**：`document.hidden` 时停止 RAF 循环，回到前台恢复。
4. **自适应降档**：持续监测帧率，连续低于 40fps 时依次关闭星尘层 → 降低星数 50% → 关闭卫星与流星，并停止继续降级。
5. **移动端降级**：视口宽度 < 768px 时星数减半、关闭星尘与流星、DPR 上限降为 1.5。
6. **无障碍优先**：`prefers-reduced-motion: reduce` 时只渲染一帧静态星空（保留视觉氛围，无任何动画）。
7. **旧浏览器兜底**：不支持 Canvas 或 JS 被禁用时，CSS 层的静态星云渐变仍然生效，页面背景不出现空白。

**性能预算**：桌面常态 60fps，单帧主线程耗时 < 6ms；本层不产生任何网络请求。

**与「零依赖」原则的说明**：本层不引入任何第三方动画库（GSAP / three.js / particles.js 等），而是自研引擎，原因有三：① 满足「CSS 集中在单一文件 + 不用 CDN」的硬约束；② 第三方库体积普遍在 100KB+，超出性能预算；③ 自研后可按场景精细调参，且无版本维护风险。所谓「调用动画组件」，落地形式即为 `data-scene="xxx"` 一行声明即完成场景调用。

#### 2.6.5 星云生成管线（v1.4 定稿）

星云是整页的背景，也是「观感是明净还是脏」的决定因素。它的生成分三个阶段，全部跑在按 8ms 预算分片的异步任务队列里：

| 阶段 | 做什么 | 关键参数 |
| --- | --- | --- |
| 0 累积密度 | 逐个色斑把「径向衰减 × 扭曲后的 fBm 密度」累加进浮点缓冲 | 扭曲频率 0.42 / 2 阶；主密度场频率 0.62 / 2 阶 / 增益 0.42 |
| 1 输出像素 | 按密度把冷 → 中 → 暖三档颜色插值，乘 `NEBULA_GAIN` 写进 RGB，alpha 置 255 | `NEBULA_GAIN = 0.20`；抖动幅度 ±0.9（一个量化步长以内） |
| 2 模糊 | 横、竖各一趟一维滑动窗口，近似高斯 | `NEB_BLUR_R = 9`（贴图坐标），越界一律取边缘像素 |

**为什么必须有阶段 2**：噪声密度场无论怎么调频率与阶数，本质都是「一堆斑块」；贴图只有 1/3 视口分辨率，放大回去时斑块边缘依旧是硬边，远看就是一片斑驳的污渍。**把阶数降下来只能让斑块变大，不能让边缘变软** —— 唯一的办法是把高频结构真正抹掉。

**密度映射的定稿形式**是「平滑映射 + 低下限」，而不是「阈值截断」：

```
dens = (0.10 + 0.90 · smoothstep((d − 0.32) / 0.64)) · fall · gain
```

早期版本用 `(d − thr) / k` 截断，阈值以下直接归零，于是星云被切成一块块互不相连的亮斑，**斑与斑之间的暗缝正是「脏兮兮」的直接来源**。改成平滑映射后不再有归零区；下限取 0.10 而不是更高，是因为下限抬得太高会把整片星云填成一坨平光色块，反而失去层次。

**验证工具**：`tools/measure-scene.cjs <scene>` 直接读渲染结果的像素分位，输出该区域的平均色、亮度 p05/p25/p50/p75/p95 以及正文色（`--text-1` / `--text-2`）相对该背景的对比度。**不要靠肉眼在缩略图上判断「亮不亮」** —— 缩略图缩放与屏幕伽马都会骗人。

## 三、字体方案（专业字体库 + 本地化）

严格遵守「使用专业字体库并本地化」的要求：**不使用任何在线字体 CDN，全部下载、子集化后自托管**。

### 3.1 字体选型

| 角色 | 字体 | 字重 | 理由 |
| --- | --- | --- | --- |
| 中文标题 | 思源黑体 Source Han Sans SC | Heavy 900 / Bold 700 / Medium 500 | 开源可商用、字形严谨、字重齐全，企业级首选 |
| 中文正文 | 思源黑体 Source Han Sans SC | Regular 400 / Light 300 | 与标题同族，阅读舒适 |
| 西文正文 | Inter | 400 / 500 / 600 | 屏幕阅读优化最佳的无衬线体之一，开源可商用 |
| 展示 / 数字 | Orbitron | 400 / 600 | 几何科幻感，用于 Logo 副标、章节序号、数据大数字 |
| 等宽数据 | JetBrains Mono | 400 / 500 | 用于字数统计、编号、代码片段 |

> 备选：若希望整体更「硬朗几何」，中文标题可换为 HarmonyOS Sans SC（同为开源可商用）。此项列入待确认清单。

### 3.2 本地化实现流程

1. 通过 `@fontsource` 包或官方发布源获取字体文件（woff2 优先）。
2. 使用 `fontTools` 做子集化：
   - 中文：`常用字 3500 字表` + 抓取全站页面实际用字，取并集生成子集；
   - 西文：Basic Latin + Latin-1 Supplement + 常用标点 + 数字符号。
3. 产物输出至 `assets/fonts/*.woff2`，每种字重单文件，全站字体总体积控制在 **1.5MB 以内**。
4. 在唯一 CSS 文件内声明 `@font-face`，统一 `font-display: swap`。
5. 关键字体（首屏标题所用字重）在 HTML `<head>` 中使用 `<link rel="preload" as="font" crossorigin>` 预加载。
6. 定义完整回退栈，保证字体加载期不出现布局跳变：
   `"Inter","Source Han Sans SC",system-ui,"PingFang SC","Microsoft YaHei",sans-serif`

### 3.3 排版细节

- 中文正文行高 1.75，西文正文 1.65
- 中英混排时西文字号略大于中文（+0.5px）以对齐视觉重心
- 数字统一使用 `font-variant-numeric: tabular-nums`，避免计数动画时宽度跳动
- 标题统一的负字距：中文 `-0.01em`，西文展示字体 `0.02em` 正字距（Orbitron 需放宽）

## 七、技术方案

### 7.1 技术栈

| 项 | 方案 |
| --- | --- |
| 页面 | 纯静态 HTML5，语义化标签，7 个页面 |
| 样式 | **单一文件** `css/style.css`，按 `tokens → reset → base → layout → components → pages → utilities → responsive → motion` 分区，用注释分隔；全部尺寸走 CSS 变量 |
| 脚本 | 原生 ES6，无任何第三方库：`js/space.js`（星球特效引擎，全站）+ `js/main.js`（全局交互）+ `js/works.js`（作品筛选）。**`js/contact.js` 已于 v1.4 随联系页去表单化一并删除** |
| 背景特效 | 自研 Canvas 2D 太空场景引擎（见 2.6），配置驱动、按页面切换场景 |
| 依赖 | 零外部依赖、零 CDN、零构建工具，双击 HTML 即可预览 |
| 图标 | 全部内联 SVG（`currentColor` 描边），无图标字体、无 emoji |
| 图片 | Logo 位图 + CSS/SVG 图形，装饰全部矢量化 |

### 7.2 CSS 组织约定

- **源文件按分区存放于 `.build/css-parts/01-tokens.css` … `08-motion.css`，由 `node tools/build-css.cjs` 合并为唯一的 `css/style.css`。** 站点只加载一个 CSS 文件（「CSS 全部集中在单一文件」是硬约定），但单一文件不好维护；改样式请改分区文件后重新合并，不要直接编辑 `css/style.css`
- 变量集中在 `:root`，含颜色、字号、间距、圆角、层级、动效时长
- 命名采用 BEM-lite（`block__element--modifier`），避免嵌套超过 3 层
- 响应式以 `min-width` 移动优先为主，复杂组件用 `clamp()` 做流体化，减少断点数量
- 关键区块使用 Container Queries 的降级友好写法（功能增强，不影响老浏览器）

| 1680–1919px | 大屏 | 容器 1440px，装饰元素延展 |
| ≥1920px | 超宽 / 4K | 容器上限 1600px 居中，星野与光晕铺满视口，避免两侧空洞 |

**关键机制**：

- 排版流体化：`clamp()` 控制字号、间距，避免断点跳变
- 网格自适应：`repeat(auto-fit, minmax(...))` 处理卡片列数
- 单屏高度：Hero 使用 `min-height: clamp(560px, 88vh, 900px)`，兼容小屏笔记本
- 高分屏：Logo 与图形按 2x 资源准备，SVG 优先
- 横屏矮屏（如 800×600）：单独处理纵向间距压缩
- 超宽屏：内容居中 + 装饰横向延展，禁止出现「内容拉满屏宽」的阅读疲劳

### 7.4 浏览器支持

Chrome / Edge 90+、Firefox 88+、Safari 14+、移动端 iOS Safari 14+ / Chrome Android。
`backdrop-filter`、`container-queries`、`aspect-ratio` 等特性均提供降级方案，降级后不破坏布局与可读性。

### 7.5 性能与无障碍

**性能目标**：首屏 HTML + CSS ≤ 120KB（字体另计）；字体预加载 + `swap`；图片懒加载；无阻塞脚本；Lighthouse 性能 / 无障碍 / 最佳实践 ≥ 90。

**无障碍要求**：语义化标签与标题层级；导航 / 表单 / 折叠面板完整 ARIA；键盘可达 + `:focus-visible` 明显焦点；正文对比度 ≥ 4.5:1（深底浅字已满足）；`prefers-reduced-motion` 关闭动效；表单错误提示与 `aria-describedby` 关联。

### 15.3 星球特效重做

**根因**：原引擎使用**值噪声（value noise）**——每个格点是一颗圆丘，球面与其相交得到的等值线是圆弧。单位球上频率 f 的噪声场只有约 `4πf²` 个格点参与，f=1.5 时不过三十来个，于是整颗球面就是三十几块圆斑，斑与斑的边界正好是一串同心圆弧，远看即「一圈圈规整的弧形色带」。这不是着色问题，**加阶数也救不了**——最低阶权重最大，圆弧始终存在。

**定位方法**：新增 `HQ_DEBUG` 出口，把高度场单独导出为灰度图。这样才把「高度场没结构」与「着色抹平了结构」两个完全不同的问题分开——灰度图上直接看到了圆丘与同心弧，根因随即确定。

**修复**：

| 项 | 改动 |
| --- | --- |
| 噪声核心 | 值噪声 → **3D 梯度噪声（Perlin）**：`grad3()` 12 方向点积 + 五次平滑插值 + `*0.5+0.5` 归一。海陆二值图变为不规则大陆、半岛与岛链，圆弧彻底消失 |
| 地形叠加 | **山脊噪声 `ridgedFbm3`**（`1-\|2n-1\|` 再平方，产生尖脊）+ 域扭曲（三层低频噪声构成偏移向量，**重新归一化回单位球面**，偏移量收敛到 0.30） |
| 海平面 | **百分位定标**：对高度场排序取 p0.16 / p65.5 / p99.88，使海陆比与噪声幅值解耦——换一次噪声实现，不必重新手调阈值 |
| 云层 | 阈值按 `HQ_DEBUG` 实测分布重定（0.520 → 0.465 / 除数 0.270），覆盖率由 <5% 提到约 13%（含 gamma 权重后的视觉覆盖约四成） |
| 极光 | 抽出 `auroraBand()`：先把坐标系压扁成椭圆再在单位圆内做环带（`a=0.36rs / b=0.26rs`，圆心偏移 `rs*0.62`）。此前的「渐变圆心放球外靠峰值半径凑弧」会从球心下方穿过，在球体中部横出一条绿带 |
| 配色 | 五套色系（purple / indigo / teal / rose / steel）整体重调，雪线抬高（原来 34% 陆地高程都进雪色），大气散射与高光收敛 |

**顺带解决的两个性能问题**：

1. **启动同步阻塞 2.9 秒 → 6–19 ms**。一张 1024×512 贴图约一千万次噪声采样，两个星球加星云全跑在启动路径上会白屏近 3 秒。改为 `PlanetTexJob` / `NebulaJob` 按 **8ms 时间预算分片**的任务队列，`requestIdleCallback` 调度；星球未就绪时先画纯色占位球再淡入，星云未就绪时整层跳过。7 个场景 × 3 个分辨率全部验证。
2. **`prefers-reduced-motion` 下星球永久停在占位球**。静态帧只渲染一次，而贴图此时还没生成完。新增 `TEX_READY_HOOKS`，`start()` 时注册「重绘静态帧」回调，任务完成后统一触发。

**离线渲染验收工具**：`tools/render-space.cjs`（Node 22 + `@napi-rs/canvas`），支持 `FRAMES` / `DUMP_MAPS` / `DUMP_PLANET` / `DUMP_NEB` / `DEGRADE` 环境变量，可导出高度场、海陆二值图、行星贴图与星云层，并打印启动同步耗时与贴图分片总成本。

### 16.1 背景与星球改为「明亮、舒适」

用户反馈原文：「星球图样看起来脏兮兮的……替换成更明亮、让用户心情舒适的样式，当前的样式会让人觉得压抑。」

排查下来是**三个互相独立的原因**叠在一起，只改其中任何一个都看不出效果：

| # | 根因 | 表现 | 修复 |
| --- | --- | --- | --- |
| 1 | **页面背景完全由星云决定，而暗角遮罩又把提亮吃掉** | 改 `--bg-*` 令牌、改 `<html>` 背景都看不到任何变化；实拍采样发现页面背景最暗处只有 L≈21，与参考图 `#13192F`（L≈25）持平 | 见 16.1.1 |
| 2 | **星云密度用阈值截断，斑块之间有归零的暗缝** | 放大到全屏就是一片斑驳的「污渍感」——这是「脏兮兮」的直接来源 | 见 16.1.2 |
| 3 | **星球陆地走低饱和暗紫** | 在中低明度上呈灰扑扑的浑浊感；暗面又一路压到 `rgba(4,6,14)`，在深色页面里就是一块黑斑 | 见 16.1.3 |

#### 16.1.1 页面背景层级的真相

`js/space.js` 的星云贴图在输出阶段把 **alpha 全程写 255**，绘制端用 `lighter` 合成 —— 结果是主画布的每个像素最终 alpha 都被推满，`<html>` / `<body>` 上的背景色在画面里完全看不到。

这条性质此前没有被记录，导致 v1.3 把 `--bg-0..3` 从 `#070B18 / #0B1026` 提到 `#101833 / #151E3E` 后**没有任何视觉效果**。本轮明确记录该层级关系（见 2.6.1 的提示框），并改为直接调光源：

- 暗角遮罩（`.bg-vignette`）上下线性遮罩 `0.46 / 0.52` → `0.32 / 0.40`，四角 `0.30 / 0.54` → `0.22 / 0.42`
- 星云整体增益系数 `NEBULA_GAIN` 0.30 → 0.20 → 0.27，并把「色斑强度 → 增益」的换算从 `a / 0.26`（上限 1.30）改为 `a / 0.20`（上限 1.85），各场景上调约三成
- 原本最暗的 `works` / `community` 两个场景色斑半径与强度单独上调（`works` 整幅 p50 亮度此前只有 15，比参考图的页面底还暗）

`--bg-*` 令牌本身也一并提亮，但它们只在 Canvas 不可用或 JS 被禁用时作为兜底生效。

#### 16.1.2 星云：从「斑块」到「雾」

原密度映射是 `(d − thr) / k`：阈值以下直接归零。fBm 的取值天然围绕 0.5 起伏，截断之后整片星云就被切成一块块互不相连的亮斑，**斑与斑之间的暗缝正是「脏」的观感来源**。

修复分三步：

1. **平滑映射替代截断**：`dens = (0.12 + 0.88 · smoothstep((d − 0.32) / 0.64)) · fall · gain`。下限取 0.12 而不是更高 —— 抬得太高会把整片星云填成一坨平光色块，反而失去层次。
2. **结构尺度整体放大**：主密度场频率 `1.05 → 0.78 → 0.62 → 0.30`、阶数 `4 → 2`、增益 `0.50 → 0.42`；域扭曲频率 `0.52 → 0.42 → 0.38`、幅度 `1.9 → 1.15 → 0.85 → 0.70`。频率 0.30 对应贴图上约 130px 一个周期，放大到 1440 视口就是 400px 量级的云团。
3. **新增阶段 2 模糊（关键）**：横、竖各一趟一维滑动窗口近似高斯，半径 13（贴图坐标），越界一律取边缘像素。**这一步不能省** —— 噪声密度场无论怎么调频率与阶数，本质都是一堆斑块，而贴图只有 1/3 视口分辨率，放大回去时斑块边缘依旧是硬边；降阶数只能让斑块变大，不能让边缘变软。

顺带修正径向衰减：`fall²` → `fall^1.55 · (0.72 + 0.28·fall)`。平方衰减会在中心压出一个硬核、边缘几乎垂直掉到零，那圈陡沿同样是「斑」的轮廓。

#### 16.1.3 星球配色：饱和度优先于明度

五套调色板（purple / indigo / teal / rose / steel）整体重做，两条新规则写进代码注释：

- **陆地各档的饱和度优先于明度**。原来的低饱和暗紫在中低明度上会呈现灰扑扑的浑浊感；把饱和度提上去、把深海与高地之间的中段提亮，整颗星球才显得干净。
- **暗面不压到纯黑**。球面明暗遮罩的末端从 `rgba(4,6,14)` 抬到 `rgba(18,24,48)`，保留一层可辨识的冷色反光 —— 星球是背景元素，全黑只会让页面显得压抑。

另外把洋流起伏从 `0.74 + 0.52·cur` 收到 `0.86 + 0.28·cur`：原摆幅会把海面打成一片深浅不匀的斑块，远看同样是「脏」的来源。

#### 16.1.4 顺带修掉的一个坑：`BG_COLOR` 不生效

`tools/render-space.cjs` 一直支持 `BG_COLOR` 环境变量把渲染结果预合成到指定底色上，但因为主画布是不透明的，这个变量**从来没有起过作用** —— 两次不同底色的渲染输出文件大小一字不差，这才发现。现在默认底色改为 `#1B2550`（页面背景渐变的中间停靠点），并把这条性质写进注释。

## 十七、v1.5 变更记录（晨曦天青配色 · 贴图精度 · 滚动离场）

### 17.1 配色风格切换：「深空蓝紫」→「晨曦天青」

用户要求「替换成其他的颜色风格，颜色风格应该更加明亮」。本轮不是在旧色上继续加亮，
而是整体换了一族色相：

| 层 | v1.4 | v1.5 |
| --- | --- | --- |
| 页面底色 | 蓝紫系（`#101833`–`#212B5E`） | 天青系（`#122642`–`#224974`，全部上移一档） |
| 星云色相 | 紫 / 靛 / 玫红为主 | 天青 `#3E9EE0` / 湖蓝 `#4A78D8` / 薄荷 `#2FC4A8` / 暖金 `#E8A45E` |
| 星球调色板 | purple / indigo / teal / rose / steel | **azure（蔚蓝）/ mint（薄荷）/ coral（珊瑚）/ dawn（晨光）/ glacier（冰川）**，海洋整体提亮一到两档，陆地改用高饱和暖色系 |
| 画布底 | 无（星云黑底即页面底） | **新增天空底色渐变** `#2A4E78 → #1C375A → #152B4A`，星云用 `lighter` 叠加在其上 |
| CSS 硬编码 | 蓝紫族 rgba | 全部批量迁移到天青族（令牌 + 各分区共 30 余处） |

**为什么必须加天空底色**：星云贴图是「黑底 + 加色色斑」，直接铺在画布上时色斑之间
就是一片近黑（v1.5 初版实测整幅 p05 只有 26–39），金色斑叠在深底上还会发浑。
先铺一层不透明的天青渐变再叠星云，全幅任何位置不再掉到近黑。

**实测**（`tools/measure-scene.cjs`，2880×1620 全幅，铺天空底色后的最终值）：整幅亮度
p05 = 66–82（v1.4 为 26–39，此前色斑之间是近黑），p50 = 107–131（v1.4 为 37–61）；
正文 `--text-1` 相对 p50 背景对比度 7.35:1，实拍页底画面干净无黑斑。

### 17.2 星球贴图精度提升

| --- | --- | --- |
| 贴图分辨率 | 1024×512 固定 | **按屏幕自适应**：≥1600px 屏 2048×1024，桌面默认 **1536×768**，窄屏 1024×512（Node 离线渲染落默认档 1536） |

### 17.3 星球滚动离场

用户要求「调节页面下滑时星球也向下移动的动画效果，使每一个页面到最底部时星球
正好移动到页面以外」。v1.4 的实现是固定系数（`sc * 0.14`），各页文档高度不同，
到底时星球的位置完全不可控。v1.5 改为**按本页滚动总量现场折算**：

```
exitK = (视口高 + 1.35R - 星球初始圆心y) / 本页scrollMax
cy    = 初始圆心y + 缓动后的滚动量 × exitK
```

- 滚动到底时星球圆心精确落在 `视口高 + 1.35R`，球体连同大气辉光、行星环
  一起恰好完全移出视口下缘（1.35R 的余量把辉光与环都算进「移出」）；
- `scrollMax` 在 build / scroll 事件中重算，图片加载、字体就绪改变文档高度
  也不会失准；短页面系数大、星球下降快，长页面平缓，但底部时刻精确对齐；
- 首屏与静态帧（sc = 0）不做除法，避免 scrollMax 未就绪时产生 NaN。

**探针验收**（新增 `tools/probes/probe-scroll.js`，需 `MOTION=1` 关闭
shoot.cjs 默认的减弱动效仿真）：

- index：scrollMax 一致（5202px）；滚到底后星球原位置取样块均色变化 **206.4**
  （对照：仅滚 8% 时变化 12.9），星球确认离场，底缘超出视口 715px；
- community：变化量 231.0 vs 对照 24.8，同样通过。

**连带修正**：`tools/shoot.cjs` 新增 `MOTION=1` 环境开关——默认仍强制
`prefers-reduced-motion: reduce` 保证截图确定性，动画类探针以此打开真实动画。

## 十八、v1.6 变更记录（异星星球 · 滚动画质稳定 · 导航高亮修正 · 内容背景融合）

### 18.1 星球样式漂移修复：「下滑到底再上滑后，星球变成了另一颗」

用户实测反馈：页面滚到底再滚回来，星球会被渲染成另外一种样式。排查出**三个叠加的根因**，
全部修复：

**根因一：FPS 自动降档会改变画面「内容」。** 旧版降档在 degrade≥2 时关闭云层与极光、
把星野数量砍半 —— 而长页滚动期间每帧都在重绘整幅画布，fps 采样几乎必然低于 40，
于是每滚一次长页就触发一次降档，星球永久变成「无云无极光、星野稀疏」的另一颗。
修复（原则：**降档只许降精度，不许换内容**）：

| 项 | v1.5 | v1.6 |
| --- | --- | --- |
| 云层 / 极光 | degrade≥2 关闭 | **所有档位保持开启** |
| 星野数量 | degrade≥2 砍半 | **所有档位不变** |
| 星尘 | degrade≥1 即关闭 | 仅 degrade 3 关闭 |
| 球面映射列数 | 64→46→32 | 64→48→40→32（渐进） |
| 画布渲染分辨率 | 不变 | **新增按档位 ×0.85 / ×0.75 / ×0.6**（最大成本项，视觉无损） |

**根因二：滚动期间仍在采样 fps。** 修复：缓动未收敛（`|tScroll - scroll| > max(2, h×0.004)`）
时跳过采样并清零窗口；降档需**连续两个**低帧窗口才生效，偶发卡顿不再付出画质代价。

**根因三：贴图就绪回调绑定旧实例。** 星球创建时若贴图任务已在队列中（引擎重建早于
贴图完成），旧任务的 `onDone` 闭包绑定的是旧 Planet 实例，新星球会永远停在纯色占位球。
修复：`TEX_READY_HOOKS` 改为可注销钩子（返回 true 继续等待 / false 注销），
等待队列的星球自行登记，就绪后接入贴图并重新淡入。

**附带根治：贴图调度器从 `requestIdleCallback` 改为 rAF 驱动**（每帧 ≤10ms 预算、
单个调度窗口内连续推进多片）。实测部分环境（headless 截图、被节流的后台标签）里
rIC 每次要等满 120–170ms、`setTimeout(0)` 也被钳到 ~50ms，325 片的贴图任务要 40 秒
以上才能就绪 —— 星球长时间停留在纯色占位球上；rAF 在这些环境里仍稳定跑满帧率，
改后贴图在慢环境下 ~5–7s 就绪，正常桌面环境成本不变。

## 十九、v2.0 变更记录（「GEO 冷峻几何」美术方向重制）

### 19.1 背景：为什么重制美术方向

星球渲染管线（Canvas 2D + 程序化贴图）历经 v1.3–v1.6 四轮迭代，仍存在两类难以根除的问题：

1. **渲染稳定性**：降档、重建、贴图就绪时序在低端设备与 headless 环境下反复出现
   「星球变成另一颗」「星球停在占位球」类缺陷，每次修复都引入新的边界条件；
2. **背景清晰度**：程序化贴图本质上是一张 1536×768（高分辨率屏 2048×1024）位图，
   经球面映射放大后细节发糊，无法在 4K 屏上保持锐利边缘。

v2.0 的决策是：**放弃「拟真星球」路线，整站美术改为几何线条与色块构成**。
矢量图形（CSS / 内联 SVG）在任何分辨率下边缘锐利、渲染零延迟、不存在状态机问题，
且与「科幻 · 冷峻 · 简洁」的品牌气质更为契合。

## 二十、v2.1 变更记录（背景星图化）

### 20.1 动机

v2.0 的背景几何构成（描边圆 + 实心方块）虽然冷峻，但「方块」本身不携带语义，
与科幻网站「科学探索 · 幻想」的气质脱节。v2.1 把背景改写为**星图样式**：
沿用真实星图的语法 —— 星点、星座连线、坐标十字、刻度弧、轨道椭圆、
天区/轨域高亮色块 —— 用极简几何元素讲「观测宇宙」的故事，色块因此有了含义
（它们是天区与轨域的高亮，不再是装饰）。

### 20.2 背景层新构成（全部矢量，层级从远到近）

| 元素 | 实现 | 内容 |
| --- | --- | --- |
| `.bg-grid` | CSS 双层线性渐变 | 84px 细网格 + 336px 主网格（坐标纸） |
| `.bg-stars` | CSS 16 枚 radial-gradient 星点 | 1–2px 白/雾蓝星点，恒定星野 |
| `.bg-constellation` | 全幅 SVG（1600×900, slice） | 13 枚背景星 + 7 枚「被命名之星」、三组星座连线、一条虚线大圆弧（天球赤道暗示）、两枚带坐标十字的命名星（r=8 描边环） |
| `.bg-shard--a` 观测坐标图（左上） | SVG | 扇形天区高亮色块 + 四星连线 + 刻度弧（dasharray 1/6）+ 坐标十字 + 天区标记小色块 |
| `.bg-shard--b` 轨道图（右中） | SVG | 中心恒星 + 十字准线、实线轨道圆 + 虚线轨道圆、倾斜轨道椭圆（rotate -18°）、在轨星点 + 卫星星点、扇形轨域高亮色块 |
| `.hero::after` 首屏星图锚点（≥1024px） | 纯 CSS | 描边大圆（天球）+ 内环 + 全幅十字准线 + 两枚轨道节点色点（冰青 5px / 雾蓝 3px，位于圆周 45° 对角上） |

v2.0 的「无语义方块」已全部移除；保留的两处小色块分别是天区标记与轨域扇形，

### 20.3 设计规则

- 星图元素 opacity 0.28–0.6，只与留白对话，不与正文争夺对比度；
- 星座连线走 `currentColor`（冰青），背景星点走固定白 `#EDF2F8` 与雾蓝，
  与内容层强调色一致；
- `.bg-stars` 与 `.bg-constellation` 在密度上分层：散星（无连线、更暗） vs
  命名星（有连线、带环与十字）—— 「每个人都看得到星星，天文学家看得到星座」；
- 首屏锚点与右下轨道图部分重叠，读作「多层观测图表叠放」，属有意构图。

### 22.22 v2.3.18 首屏探测器缩尺：以「渺小」强化日面巨物感

**需求**：进一步缩小飞船尺寸，反映「人类造物在星空和太阳前的渺小」。

**做法**：只动显示宽度与随之失效的笔画密度，**没有动任何坐标与 transform**。

| 项 | v2.3.17 | v2.3.18 |
| --- | --- | --- |

- 显示尺寸 ×0.539 后，viewBox 920 的缩放系数从 0.407 掉到 0.219：

  节点 r 2.6→3.9、信标 r 3.2→4.8、传感眼三层 10/5.6/2.6→15/8.4/3.9、

### 22.27 v2.3.23 图书馆拆解方法重订（四件产出）· 全站字体与配色修复

**本轮两个要求**：① 银河图书馆的拆解规则存在缺陷 —— 拆解的目的是「给所有文章建立关键词索引、
作品主要剧情分析、建议、修改方向」，按这个原则重订具体方法；② 检查全站字体与页面颜色，
修复字体显示错误与页面色块显示错误。

#### 一、拆解方法为什么必须重写

旧版把拆解做成了**评价体系**：六维度打分表 + 知识图谱 + 三种交付物（拆解卡 / 长图 / 报告）
+ 固定报告结构。问题不在执行，在方向 —— 这套产出服务的是「读一遍觉得专业」，
而真正需要的是一个**索引系统**：

| 旧体系的产出 | 能被检索 | 能跨作品对照 | 能告诉作者下一步改哪里 |
| --- | --- | --- | --- |
| 六维度打分 | 不能（分数不是词） | 勉强（只能比总分） | 不能（分数不指向动作） |
| 知识图谱 | 不能（图不可搜索） | 不能 | 不能 |
| 长图 / 报告 | 不能（藏在图里） | 不能 | 部分 |

打分还有一个副作用：它和「评稿」抢同一个位置。评稿才是打分的地方 ——
五维各 0–10、超过 4 份去掉最高最低、前 10% 拿奖金。拆解再打一次分，
两套分数互相矛盾，作者不知道该信哪个。

所以新体系的第一条边界是：**拆解不给分。**

#### 二、四件产出

| 产出 | 回答的问题 | 形态 |
| --- | --- | --- |
| 关键词索引 | 这篇在写什么 | 五类词 + 权重 + 同义归并 |
| 剧情分析 | 这篇怎么走的 | 三句话主线 + 剧情节点轴 + 伏笔台账 |
| 建议 | 哪儿能更好 | 结构层 / 执行层 / 细节层，3–5 条可执行路径 |
| 修改方向 | 先改哪一处 | 排序后的修改清单，每条带两种走法与影响面 |

**索引词五类**：题材与母题 / 科技与设定 / 社会与制度 / 意象与物象 / 情感与基调。

**索引四条规矩**：

1. **主词与辅词** —— 一个主词带 2–4 个辅词，辅词带权重，检索时按权重排
2. **同义归并** —— 同一概念只留一个规范词，其余进别名表，不新增平行词条
3. **用作者的词** —— 作者自造词优先收录，不做改写；索引是检索工具，不是文风校对
4. **只增义，不改义** —— 词条含义只能扩充、不能推翻，旧索引永远可复现

**剧情三句话**：谁 / 要什么 / 付出什么。三句话写不出来，说明这条主线在拆解者脑子里还没成形
—— 这时候不该去画节点轴。

**剧情节点轴**：起点 → 转折 → 危机 → 终局 四段式，事件标在轴上，
伏笔用回环线挂在「埋下」与「回收」两个节点之间，形成台账。

**建议三层**：结构层（骨架问题，改了要重写）/ 执行层（场景与节奏，改了要重写段落）/
细节层（句子与用词，改了不影响结构）。分层的作用是让作者先知道**这条建议要他付出多少**。
每条建议给 3–5 条**路径**而不是清单 —— 清单把写法定死了，作者只剩服从或无视两种选择。

**修改方向四条规矩**：排序（按影响面从大到小，不按好改程度）/ 两种走法
（每条必须给「保守」与「激进」两个方案）/ 影响面（写清改这一处会牵动哪些段落）/
决定权（拆解只给方向，改不改、怎么改由作者定）。

**六步流程**：通读定基 → 抽索引词 → 还原剧情 → 写建议 → 定修改方向 → 归档入馆。

### 八、复审时撞出来的两个真故障

1. **`/` 与 `/admin/` 各 500**：两条重定向路由写成了 `static fn`。Slim 的 `CallableResolver`
   会把路由闭包 `bindTo` 容器，而 PHP 不允许给 static 闭包绑 `$this`，于是
   「Cannot bind an instance to a static closure」。改成普通闭包，并且库根从 `/admin`
   改指向 **`/library`**（公众到的是图书馆，后台自己走 `/admin/login`）。
2. **`/healthz` 每次探活都发一个会话 cookie**：健康检查只回 JSON，不需要会话，却因为
   不在公开读白名单里而 `session_start()`。把 `/` 与 `/healthz` 一并加进
   `SessionMiddleware::isPublicRead()`，探活不再写 session 文件、不再下发 `hq_admin`。
